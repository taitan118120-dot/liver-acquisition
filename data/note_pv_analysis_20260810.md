## 0. 前提の訂正

依頼文にあった「どの記事が読まれているかを一度も測っていない」「公開108本」は、いずれも実態と違った。

- PVは 2026-07-13 / 07-23 / 08-04 / 08-08 に測定済みで、直近の記事補充（#135-149）はその実測に基づいて選ばれている
- 公開本数は **124本**。`data/published_note_keys.json` の108件は登録が遅れている台帳で、
  実体は note の `creators/contents` API が返す124本（毎日8:03の自動投稿が進んだぶん台帳が追いついていない）

今回は「初回測定」ではなく、**前回（08-08）から2日後の再測定＋キーワードプールへの反映**として実施した。

## 5. AI（GEO）に引用される構造の検査

上位15本と下位15本の本文HTMLを取得して構造を比較した（`/api/v3/notes/{key}`）。

| 指標 | 上位15 中央 | 下位15 中央 | 判定 |
|---|---:|---:|---|
| 文字数 | 4,620 | 3,464 | ○ 差あり |
| H2見出し数 | 9 | 6 | ○ 差あり |
| **具体数値の数** | **39** | **15** | ◎ **最大の差** |
| 箇条書きの項目数 | 3 | 3 | ✗ 差なし |
| 箇条書きブロック数 | 1 | 1 | ✗ 差なし |
| 「〇〇とは」定義文 | 0 | 0 | ✗ **全滅** |
| Q&A | 4 | 5 | ✗ 差なし |
| 表 | 0 | 0 | ✗ 全滅 |

**結論: 3要素のうち揃っているのは「数値」だけ。「定義」と「箇条書き」は上位記事にも無い。**

- **数値** … 上位は下位の2.6倍。金額・期間・人数が入るほど読まれている。相関が最も強い
- **箇条書き** … 検出された `<ul>` は全記事で1つ、項目3つ。中身を確認したところ**全部「あわせて読みたい」の内部リンクブロック**で、本文の箇条書きは実質ゼロだった。
  原因は `note_article_generator.py` のプロンプトが「箇条書きは1セクションに1回までに抑える」と**抑制していた**こと
- **定義文** … 「〇〇とは、〜です」の形が上位・下位ともほぼ0。プロンプトが一度も要求していなかった

AI経由（GEO）で実入会が発生している以上、**AIが答えとして切り出せる塊が本文に無いのは取りこぼし**。
数値だけで上位に来ているなら、定義文と箇条書きを足せばさらに拾われる余地がある。

## 6. 実施した変更

### `note_article_generator.py`

1. **`CATEGORY_WEIGHTS` を実測値に差し替え**
   ```
   旧: income3 sidejob3 beginner3 / lifestyle2 troubleshooting2 agency2 / skills1 platform1 comparison1 advanced1
   新: lifestyle4 platform4 / income3 skills3 beginner3 / comparison2 agency2 advanced2 / troubleshooting1 sidejob1
   ```
   実測で最下位級だった sidejob が最優先だった点と、最強だった lifestyle が2だった点を修正。

2. **キーワードごとに優先度 `p`（3/2/1）を追加**し、抽選確率を「カテゴリ重み × p」に変更。
   40-50代／TikTok LIVE／Pococha／顔出しなし／配信テク／収入の具体額に p=3 を寄せた。

3. **プールを 109 → 106 に入れ替え**（外した28件 / 足した25件）
   - 取り扱い外プラットフォーム5件（IRIAM・SHOWROOM・ふわっち・ツイキャス・ミクチャ）を除去
   - 「副業 月5万」系2件を除去（確定レンジ 3ヶ月15〜20万 を下回るため全媒体で使わない表現だった）
   - 税金・制度／事務所の選び方量産型／総花的な悩み系を退役
   - 40-50代6本、TikTok LIVE 6本、Pococha新人期間3本、配信テク5本などを補充

4. **プロンプトのGEO対応**（5章の検査結果を反映）
   - 「箇条書きは1セクション1回まで」→「記事全体で3〜5箇所必須、1つ3〜6項目」に反転
   - キーワードの1文定義（「〇〇とは、△△な人が□□するための××です」）を必須化
   - 具体数字を「最低5箇所」→「最低20箇所」（上位中央39・下位中央15に合わせた）
   - 文字数 2,500〜3,500 → 4,000〜5,000（上位中央4,620字）
   - 各H2セクションは結論を最初の2〜3行で言い切る指示を追加

5. **プロンプトが確定ファクト違反を教えていた箇所を修正**
   - 体験談の例文「Pocochaで月300万円稼いでいた頃の1日は、18時間配信でした」
     → 代表の最高月収は「3桁」表記のみ可・具体額と配信時間はNGという確定ファクトに反していた。
       確定レンジ内の例文に差し替え
   - タイトル型Dの例「9割の人が半年で消える」
     → `facts_patterns.ratio_violations` が検出対象にしている出典なしの割合統計そのものだった。差し替え＋明示的に禁止
   - 【確定ファクト】ブロックと【絶対NG】の追記（還元率100%+α／所属200名／収入レンジ／
     リスナーさん表記／手数料なし系の言い換え禁止／取り扱い外アプリ禁止）

### `data/note_keyword_tracker.json`

- `covered`（22件）… Claude直書き等の別経路で既に同テーマを公開済みのキーワード。公開124本のタイトルと全語一致で突合
- `pv_baseline` … 今回の実測サマリ。次回補充時はここを見て、測り直してから決める
